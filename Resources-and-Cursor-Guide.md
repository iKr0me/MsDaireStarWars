## What connects to Cursor versus the website

Cursor edits local files. Project libraries are installed into the project. Vercel, Supabase, and OpenAI connect to the running website through code and environment settings. An MCP connection is optional access for the coding assistant; it does not replace the website's credentials or backend.

The live flow is: visitor submits → Vercel server validates and screens → Supabase saves pending → organizer approves in Supabase → the reader retrieves the approved note. The browser never receives the privileged API keys.

No separate OpenRouter purchase, Roo Code extension, Cline extension, Vercel MCP, Supabase Auth application login, custom /admin page, or paid model generator is needed for this first version.

1. Extract the complete kit and read `START-HERE.md` and `MORNING-CHECKLIST.md`. Keep its folders together.
2. In Cursor, open the kit's root folder. The original prototype is preserved under `reference/roo-prototype/`; the new app belongs in `website/`.
3. Open Codex in Cursor and sign in with ChatGPT. Choose GPT-6.1 Sol with Medium thinking if available; keep one main agent on the working files.
4. Attach or @-mention the root implementation prompt. Have the agent inspect the kit and outline the first demo slice, then build it. Do not load the old prototype script/configuration or introduce React.
5. Have Cursor check Node/Git, initialize Git at the kit root if needed, scaffold Vite inside `website/`, install local dependencies, copy the selected models, configure supplied audio, and document exact startup commands. No global Three.js, GSAP, or Vite installation is needed.
6. Build one complete demo slice: real 3D hero drift → press R2 → heart arrives from his current world position → read/close → count once → reopen from collection. Use labeled sample notes and no production credentials.
7. Add Falcon form delivery and reversible crawl/hyperspace/farewell. Review motion, mobile layout, and reading comfort, with a Git checkpoint after each working stage.
8. Create Supabase, OpenAI API, GitHub, and Vercel accounts when ready for live integration. Existing accounts are fine. Supabase dashboard access is your organizer access.
9. Ask Cursor to create `website/SETUP.md`, migrations, private storage policies, database publication guards, `.env.example`, and ignore rules. Apply the documented migrations to the intended Supabase project and configure the private bucket's size/type limits.
10. Enter keys privately as described in `website/SETUP.md`. Start the documented server-backed development mode, then test a real submission, Table Editor approval, and reading in another browser.
11. Push the kit repository with secrets excluded. Import it into Vercel with **Root Directory `website`**, use the documented build settings, add production environment variables, and deploy.
12. Test the deployed site while signed out. Pending notes/photos must stay private, approval must publish them, and unpublishing must remove them from future API retrieval. Keep the separate labeled offline demo for presentations.

## The settings you will enter

Cursor's generated .env.example determines the exact variable names. Typical values are:

| Value | Where you get it | Visibility |
| --- | --- | --- |
| Supabase project URL | Project's Connect/API settings | Public identifier |
| Supabase publishable key, if used | Project API keys | May be public with appropriate access policies |
| Supabase secret key | Project API keys | Server only; privileged |
| OpenAI API key | OpenAI developer platform | Server only |
| SITE_URL | Your local or deployed website address | Public configuration |
| Anonymous-cookie signing secret | Random secret generated locally | Server only |
| Rate-limit hash secret, if implemented | Random secret generated locally | Server only |

Put production secrets into Vercel's environment settings and local secrets in an ignored local environment file. Redeploy for production environment changes to take effect. Do not paste secret values into chats or commit them to Git. An OpenAI website moderation key is separate from Cursor's coding-model subscription or model-key settings.

The standalone [OpenAI moderation endpoint](https://developers.openai.com/api/docs/guides/moderation) is free subject to access/rate limits; it is not a complete appropriateness filter. The organizer remains the final publishing decision.

## Optional: connect Supabase directly to Cursor

Start without this if the dashboard/SQL setup is clear. MCP is useful later for inspecting a development database or diagnosing a problem.

Use the [official Supabase MCP setup](https://supabase.com/docs/guides/ai-tools/mcp), select your development project, choose read-only access initially, and use its Cursor setup option. Authenticate through the offered Supabase sign-in flow. Manage the connection in Cursor's Customize/MCP interface. Labels can vary by installed version. [Cursor MCP documentation](https://cursor.com/docs/mcp).

A project-scoped configuration can go in .cursor/mcp.json:

```json
{
  "mcpServers": {
    "supabase-development": {
      "url": "https://mcp.supabase.com/mcp?project_ref=YOUR_PROJECT_REF&read_only=true&features=database,docs"
    }
  }
}
```

Replace YOUR_PROJECT_REF with the development project's reference, not its secret key. Then authenticate if prompted and ask Cursor to list the project's tables. Read-only mode cannot create tables or approve notes; use reviewed migrations through your dashboard for changes. Use sample data in this development project. Real contributors' notes/photos do not need to be exposed to the coding assistant. MCP setup is independent of the website's runtime keys and does not give visitors an approval route.

## One agent or multiple?

Use one main builder. Keep the full brief and current plan in files, then request one feature or fix at a time. This keeps costs and conflicting edits manageable. Opening five agents does not automatically produce better design.

An optional second agent can review a finished stage without editing files. Give it a narrow job, such as finding ways a visitor could read a pending note or checking why rereading increments a count. Send its concrete findings back to the main builder. A stronger model in a separate review chat can serve this role; it does not need to run simultaneously.

Only introduce parallel builders when work can be separated into independent files/branches and you are comfortable combining their changes. For this first project, one builder plus occasional review is the recommendation.

## Latest interaction, submission, and audio requirements

- Cloudflare Turnstile and CAPTCHA are omitted; no account, widget, or keys are needed for them.
- Allow five successfully saved notes per anonymous browser identity in a rolling 24 hours. Enforce this atomically in Supabase using a server-issued signed cookie. This is not a verified per-person limit: clearing cookies or changing browsers/devices can bypass it. Never apply the five-note cap to a whole school network. Failed saves and duplicate retries do not use another quota slot; saved notes keep counting even if later rejected or deleted.
- Persist idempotency keys and return the existing saved receipt on retries. Disable Send while processing; prevent duplicate saves and duplicate Falcon success animations. Keep separate burst/upload limits for failed requests.
- Lock R2 synchronously on the first accepted press. Ignore later presses and sounds throughout loading, flight, opening, reading, closing, and departure. Unlock only when the current heart has fully closed and left. Collection reopens use the same lock.
- Hearts use reusable HTML/CSS/SVG paper shapes with perspective transforms. Insert each selected record's message, sender name, and optional approved photo as live content. No heart model or separately generated letter image is required.
- Use the two included CC0 droid-style MP3 options through `audio/audio-manifest.json`, with the original WAV as a fallback. These are substitutes, not the selected YouTube recordings. Keep the music source null until a permitted Force Theme file is supplied; no broken requests or hidden YouTube player. Configured music starts from Enable music, loops through one shared player, and has controls separate from effects. See `Audio-and-Heart-Notes.md` and `audio/REFERENCES.md`.
- Test the sixth submission, exact rolling-window expiry, parallel requests, duplicate retries after quota exhaustion, rapid R2 presses in every state, reduced-motion closing, audio unavailable/blocked, and looping without overlapping players.
